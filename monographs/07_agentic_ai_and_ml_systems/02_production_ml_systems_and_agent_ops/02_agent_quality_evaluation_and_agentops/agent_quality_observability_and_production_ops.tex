\section{Problem Formulation \& Unified Notation}
\label{sec:ops:formulation}
% =============================================================================

Deploying autonomous AI agents into production breaks the foundational assumption of classical software engineering: deterministic verification against a static specification. Whereas traditional software executes a fixed control-flow graph, an active agent couples a stochastic foundation model policy $\pi_\theta$ with multi-step planning, external tool invocation $\mathcal{T}$, and mutable short- and long-term memory $\mathcal{M}$ \bookcite{agent_quality}{pp.~11--13}. Across a horizon of $H$ reasoning-and-action turns, the agent generates a trajectory
\begin{equation}
  \tau = \bigl(s_0,\, z_1, a_1, o_1,\, z_2, a_2, o_2,\, \dots,\, z_H, a_H, o_H,\, y\bigr),
  \label{eq:ops:trajectory}
\end{equation}
where $s_0$ is the user intent and system context, $z_t$ is the internal reasoning state (``Thought''), $a_t \in \mathcal{A} \cup \mathcal{T}$ is the selected action or parameterized tool call, $o_t$ is the external environment observation, and $y$ is the final user-facing output \bookcite{agent_quality}{pp.~12, 19--20}. Because stochasticity compounds at every step $t \in \{1,\dots,H\}$ and external APIs introduce non-stationary state, evaluation shifts from deterministic \emph{verification} (``Did we build the product right?'') to probabilistic \emph{validation} (``Did we build the right product?'') \bookcite{agent_quality}{p.~16}.

\subsection{The Four Pillars of Agent Quality \& Outside-In Hierarchy}
\label{sec:ops:pillars}

To anchor technical metrics in business value, agent quality is evaluated across four coupled pillars \bookcite{agent_quality}{pp.~14--15}:
\begin{enumerate}
  \item \textbf{Effectiveness (Goal Achievement):} Black-box task completion against user intent (e.g., pull-request acceptance rate, transaction completion, CSAT).
  \item \textbf{Efficiency (Operational Cost):} Resource footprint per resolved task, measured by total tokens $N_{\mathrm{tok}}(\tau)$, end-to-end latency $L(\tau)$ (P50/P99), and trajectory length $H$.
  \item \textbf{Robustness (Reliability):} Graceful degradation under noisy inputs, API timeouts, malformed tool schemas, and ambiguous prompts.
  \item \textbf{Safety \& Alignment (Trustworthiness):} Non-negotiable compliance with policy boundaries, prompt-injection resistance, PII protection, and demographic fairness.
\end{enumerate}

The \emph{Outside-In} evaluation hierarchy operationalizes these pillars in two stages \bookcite{agent_quality}{pp.~17--20}: first scoring the black-box final outcome $y$ against task intent, and only then opening the ``glass box'' to diagnose intermediate trajectory failures in planning ($z_t$), tool selection/parameterization ($a_t$), tool-response interpretation ($o_t$), or retrieval-augmented generation (RAG) grounding.

\subsection{Compounding Horizon Decay: \texttt{pass@k} vs.\ \texttt{pass\textasciicircum k}}
\label{sec:ops:passk}

In single-turn classification, error rates are additive across samples. In multi-step agent trajectories, errors compound multiplicatively across the horizon $H$.

\begin{coremath}[Derivation: Horizon Reliability Decay and Production Consistency]
Suppose an agent must execute $H$ sequential dependent steps (e.g., plan $\to$ tool call $\to$ observation parsing $\to$ synthesis) where each step succeeds independently with conditional probability $p_{\mathrm{step}} \in (0,1)$. The probability that a single trajectory $\tau$ succeeds end-to-end is
\begin{equation}
  p_\tau = \prod_{t=1}^{H} p_t \approx p_{\mathrm{step}}^{H}.
  \label{eq:ops:horizon_decay}
\end{equation}
To characterize non-deterministic capability versus production reliability across $k$ independent rollouts $\tau^{(1)},\dots,\tau^{(k)} \sim \pi_\theta(\cdot \mid s_0)$, we distinguish two estimators:
\begin{align}
  \mathrm{pass@}k &= \Prob\bigl(\exists\, i \in \{1,\dots,k\} : \mathrm{Success}(\tau^{(i)}) = 1\bigr) = 1 - (1 - p_\tau)^k, \label{eq:ops:pass_at_k} \\
  \mathrm{pass\textasciicircum}k &= \Prob\bigl(\forall\, i \in \{1,\dots,k\} : \mathrm{Success}(\tau^{(i)}) = 1\bigr) = p_\tau^k = p_{\mathrm{step}}^{k H}. \label{eq:ops:pass_pow_k}
\end{align}
For $p_{\mathrm{step}} = 0.95$ and $H = 10$ steps, $p_\tau = 0.95^{10} \approx 0.599$. Over $k=5$ trials, $\mathrm{pass@}5 \approx 0.990$ (looks production-ready in a demo), whereas $\mathrm{pass\textasciicircum}5 \approx 0.077$ (fails $>92\%$ of 5-run SLA streaks).
\end{coremath}

This exponential gap between $\mathrm{pass@}k$ and $\mathrm{pass\textasciicircum}k$ explains why prototype demos mislead engineering teams \bookcite{prototype_production}{p.~6, 38} and why production CI/CD gates must enforce multi-run consistency alongside mean task success \bookcite{reinforcement_learning_from_human_feedback}{Ch.~16, p.~198}.

\subsection{LLM-as-a-Judge Debiasing, Cohen's $\kappa$, and Statistical Power}
\label{sec:ops:judge_math}

Automated metrics (ROUGE, BLEU, BERTScore) act as fast, low-cost regression trend filters in CI/CD, but fail to capture reasoning quality or tool-use validity \bookcite{agent_quality}{p.~22}. Scaling qualitative judgment requires LLM-as-a-Judge (for final responses) and Agent-as-a-Judge (for full execution traces) \bookcite{agent_quality}{pp.~23--25}. However, pointwise 1--5 scoring exhibits high variance and calibration drift, while naive pairwise comparison suffers from position bias (favoring the first response) and verbosity bias.

\begin{coremath}[Symmetric Pairwise Estimator and HITL Alignment ($\kappa$)]
Given two agent versions $A$ and $B$ evaluated on query $x$, let $J_\phi(y_1, y_2 \mid x) \in \{1, 0.5, 0\}$ denote the judge score favoring slot 1, tie, or slot 2. To cancel first-slot position bias $\beta_{\mathrm{pos}}$, evaluate both permutations and compute the debiased win rate:
\begin{equation}
  \hat{w}_{A \succ B}(x) = \frac{1}{2}\Bigl[J_\phi(y_A, y_B \mid x) + \bigl(1 - J_\phi(y_B, y_A \mid x)\bigr)\Bigr].
  \label{eq:ops:debiased_win}
\end{equation}
To validate that the automated judge aligns with Human-in-the-Loop (HITL) domain experts on a calibrated Golden Set $\mathcal{D}_{\mathrm{gold}}$ of size $N$, compute chance-corrected inter-rater agreement via Cohen's $\kappa$:
\begin{equation}
  \kappa = \frac{p_o - p_e}{1 - p_e}, \qquad p_o = \frac{1}{N}\sum_{i=1}^{N}\mathbb{I}[c_{\mathrm{LLM}}^{(i)} = c_{\mathrm{HITL}}^{(i)}], \quad p_e = \sum_{c \in \mathcal{C}} \hat{p}_{\mathrm{LLM}}(c)\,\hat{p}_{\mathrm{HITL}}(c).
  \label{eq:ops:cohen_kappa}
\end{equation}
When comparing a candidate agent $\pi_{\mathrm{cand}}$ against production $\pi_{\mathrm{prod}}$ over $N$ i.i.d.\ Golden Set tasks with observed win-rate difference $\Delta \hat{w} = \hat{w} - 0.5$ and per-prompt variance $\sigma_w^2$, a two-sided CI/CD promotion gate at significance level $\alpha$ and power $1-\beta$ requires sample size
\begin{equation}
  N \ge \frac{(z_{1-\alpha/2} + z_{1-\beta})^2\,\sigma_w^2}{(\Delta w_{\min})^2},
  \label{eq:ops:sample_power}
\end{equation}
where $\Delta w_{\min}$ is the minimum detectable improvement above the 0.25--1.5 percentage-point evaluation noise floor observed in reasoning-era benchmarks \bookcite{reinforcement_learning_from_human_feedback}{Ch.~16, p.~198}.
\end{coremath}

\begin{intuition}[Why Pairwise Judging Beats Pointwise Scoring]
\bookcite{agent_quality}{p.~24} emphasizes that a small prompt or model change rarely shifts a noisy 1--5 pointwise score beyond its calibration jitter. Forcing a relative choice between Answer $A$ (production) and Answer $B$ (candidate) cancels shared query difficulty and yields a high-signal win/loss/tie rate, directly analogous to how RLHF preference models reduce noise during post-training \bookcite{reinforcement_learning_from_human_feedback}{Ch.~16, p.~199}.
\end{intuition}

\subsection{Slice-Based Risk, Simpson's Paradox, and Confidence Deferral}
\label{sec:ops:slicing_math}

Aggregate pass rates routinely conceal catastrophic failures on minority user cohorts, rare languages, or high-stakes tool categories \bookcite{chip_huyen_designing_machine_learning_systems}{pp.~205--207}.

\begin{coremath}[Simpson's Reversal Condition and Optimal HITL Deferral]
Partition the evaluation distribution into slices $g \in \mathcal{G}_{\mathrm{slice}}$ with traffic weights $w_g = \Prob(g) > 0$. The aggregate success rate of policy $\pi$ is $S(\pi) = \sum_g w_g S_g(\pi)$. Simpson's paradox occurs when candidate $\pi_B$ beats $\pi_A$ on every individual slice ($S_g(\pi_B) > S_g(\pi_A)\;\forall g$), yet loses in aggregate ($S(\pi_B) < S(\pi_A)$) because evaluation traffic weights $w_g^{(A)} \neq w_g^{(B)}$ differ across slices \bookcite{chip_huyen_designing_machine_learning_systems}{pp.~206--207}.

To prevent silent slice regressions and bound safety risk, each prediction or tool call with calibrated confidence $\hat{p}(x) \in [0,1]$ (verified via reliability diagrams or Platt scaling \bookcite{chip_huyen_designing_machine_learning_systems}{p.~204}) is routed to HITL review whenever $\hat{p}(x) < \tau_{\mathrm{conf}}(r_a)$, where $r_a \in \{\mathrm{low}, \mathrm{med}, \mathrm{high}\}$ is the tool risk tier \bookcite{practical_guide_building_agents}{pp.~26, 31}. Under false-execution cost $C_{\mathrm{err}}(r_a)$ and human-review cost $C_{\mathrm{HITL}}$, the Bayes-optimal deferral threshold satisfies
\begin{equation}
  \tau_{\mathrm{conf}}(r_a) = 1 - \frac{C_{\mathrm{HITL}}}{C_{\mathrm{err}}(r_a)}.
  \label{eq:ops:deferral_threshold}
\end{equation}
High-risk irreversible tools ($C_{\mathrm{err}} \gg C_{\mathrm{HITL}}$, e.g., \texttt{execute\_payment} or \texttt{delete\_database\_entry}) drive $\tau_{\mathrm{conf}} \to 1$, mandating unconditional HITL approval \bookcite{agent_quality}{p.~27}; \bookcite{practical_guide_building_agents}{p.~31}.
\end{coremath}

\subsection{Outside-In Trajectory Evaluator \& Guarded Canary Gate}
\label{sec:ops:algo_gate}

Production AgentOps unifies offline CI/CD gating \bookcite{prototype_production}{pp.~12--15} with online canary monitoring and automated rollback \bookcite{prototype_production}{pp.~16, 20--24}. Algorithm~\ref{alg:ops:outside_in_gate} formalizes this end-to-end promotion pipeline.

\begin{algorithm}[htbp]
\caption{Outside-In Trajectory Evaluator \& Guarded Canary Promotion Gate}
\label{alg:ops:outside_in_gate}
\KwIn{Candidate agent $\pi_{\mathrm{cand}}$, production baseline $\pi_{\mathrm{prod}}$, Golden Set $\mathcal{D}_{\mathrm{gold}}$ with slices $\mathcal{G}_{\mathrm{slice}}$, risk-tiered guardrails $G$, thresholds $(\tau_{\mathrm{win}}, \tau_{\mathrm{slice}}, \tau_{\mathrm{err}}, \kappa_{\min})$.}
\KwOut{Deployment decision $\in \{\textsc{Promote}, \textsc{Block}, \textsc{Rollback}\}$.}
\BlankLine
\tcp{Phase 1: Offline Pre-Merge CI Gate (Outside-In + Glass-Box)}
\ForEach{$(x, y^\star, \tau^\star, g) \in \mathcal{D}_{\mathrm{gold}}$}{
  Execute $\pi_{\mathrm{cand}}(x)$ in isolated sandbox with OpenTelemetry tracing $\to (\hat{y}, \hat{\tau})$\;
  Run deterministic checks: schema validity, regex/PII filter, perturbation invariance\;
  \If{safety/PII violation $\lor$ automated metric drops below regression floor}{
    \Return{\textsc{Block} (Phase 1 deterministic/safety failure)}\;
  }
  Compute debiased pairwise win $\hat{w}(x)$ via Eq.~\eqref{eq:ops:debiased_win} and Agent-as-a-Judge trace score $J_{\mathrm{trace}}(\hat{\tau}, \tau^\star)$\;
}
\If{$\kappa(J_\phi, \mathrm{HITL}) < \kappa_{\min}$ \textbf{or} $\min_{g \in \mathcal{G}_{\mathrm{slice}}} S_g(\pi_{\mathrm{cand}}) < \tau_{\mathrm{slice}}$ \textbf{or} $\bar{w} < \tau_{\mathrm{win}}$}{
  \Return{\textsc{Block} (Insufficient slice quality or judge calibration)}\;
}
\BlankLine
\tcp{Phase 2--3: Canary Rollout (1\% $\to$ 10\% $\to$ 100\%) with Guardrails \& OTel}
Route $1\%$ live traffic to $\pi_{\mathrm{cand}}$ with concurrent optimistic \texttt{@input\_guardrail} and tool-risk gates\;
Monitor P99 latency, error rate $e_{\mathrm{can}}$, and guardrail tripwire rate over window $\Delta t$\;
\uIf{$e_{\mathrm{can}} > \tau_{\mathrm{err}}$ \textbf{or} prompt-injection tripwire spike \textbf{or} high-risk tool anomaly}{
  Trigger circuit-breaker feature flag; capture OTel trace $\mathcal{G}_{\hat{\tau}}$ into $\mathcal{D}_{\mathrm{gold}}$\;
  \Return{\textsc{Rollback} (Instant revert to $\pi_{\mathrm{prod}}$ + Evolve loop)}\;
}
\Else{
  Promote $\pi_{\mathrm{cand}}$ to $100\%$ traffic and update Model Card\;
  \Return{\textsc{Promote}}\;
}
\end{algorithm}

\subsection{Holistic Evaluation \& OpenTelemetry Observability Pillars}
\label{sec:ops:otel}

Just as a gourmet chef cannot be judged solely by a temperature checklist (``Line Cook'' monitoring), an autonomous agent requires \emph{true observability} built on three OpenTelemetry pillars \bookcite{agent_quality}{pp.~31--40}:
\begin{itemize}
  \item \textbf{Logs (The Agent's Diary):} Structured JSON events capturing prompts, tool arguments, intermediate reasoning, and errors, scrubbed for PII.
  \item \textbf{Traces (Following the Footsteps):} Causal Directed Acyclic Graphs of nested spans (\texttt{invocation} $\to$ \texttt{agent\_run} $\to$ \texttt{call\_llm} $\to$ \texttt{execute\_tool}) linking every step to a single \texttt{trace\_id}.
  \item \textbf{Metrics (The Health Report):} Split into \emph{System Metrics} (P50/P99 latency, error rate, tokens/task, API cost) for SRE operational dashboards, and second-order \emph{Quality Metrics} (correctness, trajectory adherence, safety) for AgentOps dashboards \bookcite{agent_quality}{pp.~38--41}.
\end{itemize}

\section{Numerical Pitfalls, Edge Cases \& Failure Modes}
\label{sec:ops:pitfalls}
% =============================================================================

\begin{pitfall}[LLM-as-a-Judge Position, Verbosity \& Self-Preference Bias]
Uncalibrated LLM judges systematically favor the first candidate in a prompt, reward verbose responses over concise correct ones, and exhibit self-preference for outputs from the same model family \bookcite{agent_quality}{p.~24}. \textbf{Remedy:} Always run symmetric slot-swapped pairwise evaluation (Eq.~\eqref{eq:ops:debiased_win}), enforce length-neutral rubrics, and audit judge agreement against HITL domain experts via Cohen's $\kappa$ (Eq.~\eqref{eq:ops:cohen_kappa}) on every Golden Set release.
\end{pitfall}

\begin{pitfall}[Benchmark Saturation, Harness Drift \& 8-Gram Contamination]
Public benchmarks saturate rapidly and cannot distinguish genuine capability gains from web-scraped leakage or prompt-format overfitting \bookcite{reinforcement_learning_from_human_feedback}{Ch.~16, pp.~198--202}. Moreover, changing the agent harness, sandbox, or inference token budget can swing scores by more than model weight updates. \textbf{Remedy:} Run 8-gram and 50-character substring decontamination, maintain private held-out Golden Sets, and pair static benchmarks with perturbation tests \bookcite{chip_huyen_designing_machine_learning_systems}{pp.~201--202}.
\end{pitfall}

\begin{pitfall}[Simpson's Paradox \& Aggregate Canary Masking]
A candidate agent can improve overall task success rate while severely degrading a minority demographic, mobile traffic, or paid-user slice \bookcite{chip_huyen_designing_machine_learning_systems}{pp.~205--207}. Because error costs escalate by roughly an order of magnitude per lifecycle stage \bookcite{chip_huyen_designing_machine_learning_systems}{p.~371}, shipping an un-sliced regression is costly. \textbf{Remedy:} Enforce per-slice minimum thresholds ($\min_g S_g$) in CI/CD (Algorithm~\ref{alg:ops:outside_in_gate}) and publish updated Model Cards documenting unitary and intersectional results \bookcite{chip_huyen_designing_machine_learning_systems}{pp.~371--372}.
\end{pitfall}

\begin{pitfall}[Non-Idempotent Tool Retries \& Guardrail Latency Spikes]
Retrying a failed network call on a non-idempotent tool (e.g., \texttt{initiate\_refund}) causes duplicate financial transactions \bookcite{prototype_production}{p.~21}, while running sequential LLM guardrails on every turn inflates P99 latency. \textbf{Remedy:} Enforce idempotency keys on all write tools with exponential backoff, execute \texttt{@input\_guardrail} checks concurrently via optimistic execution \bookcite{practical_guide_building_agents}{p.~31}, and pair high-risk tools with circuit-breaker feature flags and HITL approval pauses \bookcite{prototype_production}{p.~22}; \bookcite{agent_quality}{p.~27}.
\end{pitfall}
