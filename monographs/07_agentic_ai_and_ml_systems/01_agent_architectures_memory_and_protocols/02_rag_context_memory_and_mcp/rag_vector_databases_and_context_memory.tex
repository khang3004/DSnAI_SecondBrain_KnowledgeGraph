\section{Problem Formulation \& Unified Notation}
\label{sec:rag:formulation}
% =============================================================================

Large Language Models (LLMs) are inherently stateless functions whose reasoning at inference turn $t$ is strictly bounded by the tokens inside a finite context window of capacity $B_{\max}$ \bookcite{context_engineering_sessions_memory}{p.~7}. To ground generation in proprietary, dynamic, or user-specific knowledge without retraining model weights, production agentic systems unify two complementary mechanisms: \emph{Retrieval-Augmented Generation (RAG)} over an external document corpus $\mathcal{C} = \{d_1, \dots, d_N\}$ \bookcite{speech_language_processing_aug26}{Ch.~11, PDF p.~275}, and \emph{Context Engineering} over stateful session histories $\mathcal{S}_t$ and consolidated long-term memories $\mathcal{M}_t$ \bookcite{context_engineering_sessions_memory}{pp.~7--10}.

Formally, given a user query $q_t$ at turn $t$, a retrieval pipeline selects an ordered subset of passages $\mathcal{R}_{\mathrm{rag}}(q_t, \mathcal{C}) = (d_{\pi(1)}, \dots, d_{\pi(k)}) \subset \mathcal{C}$, while a memory manager retrieves relevant persisted facts or workflows $\mathcal{R}_{\mathrm{mem}}(q_t, \mathcal{M}_t)$ and a session compactor produces a bounded conversational trace $\mathcal{K}_{\mathrm{comp}}(\mathcal{S}_t)$. Context Engineering then solves a token-budgeted payload assembly problem:
\begin{equation}
\begin{aligned}
  C_t &= \mathcal{A}\!\Big(I_{\mathrm{sys}},\, \mathcal{T},\, \mathcal{R}_{\mathrm{mem}}(q_t, \mathcal{M}_t),\, \mathcal{K}_{\mathrm{comp}}(\mathcal{S}_t),\, \mathcal{R}_{\mathrm{rag}}(q_t, \mathcal{C}),\, q_t\Big), \\
  &\qquad \text{s.t.} \quad \abs{C_t}_{\mathrm{tok}} \le B_{\max} - B_{\mathrm{out}},
\end{aligned}
  \label{eq:rag:context_assembly}
\end{equation}
where $I_{\mathrm{sys}}$ denotes system instructions, $\mathcal{T}$ denotes tool schemas, and $B_{\mathrm{out}}$ reserves tokens for model generation \bookcite{context_engineering_sessions_memory}{pp.~8--9}. The LLM subsequently generates output tokens $x_1, \dots, x_n$ autoregressively under the conditional distribution
\begin{equation}
  p(x_1, \dots, x_n \mid C_t) = \prod_{i=1}^{n} p(x_i \mid C_t, x_{<i}),
  \label{eq:rag:gen_prob}
\end{equation}
which grounds factual claims in $\mathcal{R}_{\mathrm{rag}}(q_t, \mathcal{C})$ and personalizes behavior via $\mathcal{R}_{\mathrm{mem}}(q_t, \mathcal{M}_t)$ (see \bookcite{speech_language_processing_aug26}{Ch.~11, PDF p.~276} for the baseline RAG formulation).

\subsection{Sparse Lexical Retrieval: TF-IDF and Okapi BM25}
\label{sec:rag:bm25}

Classic lexical retrieval represents queries and documents as high-dimensional sparse vectors indexed by vocabulary terms $t \in \mathcal{V}$ \bookcite{speech_language_processing_aug26}{Ch.~11, PDF pp.~263--264}. Because raw term counts $\mathrm{count}(t, d)$ scale linearly and over-emphasize repetitive words, logarithmic term frequency and inverse document frequency ($\mathrm{idf}_t$) attenuate common terms across a corpus of $N = \abs{\mathcal{C}}$ documents.

\begin{coremath}[Okapi BM25 Lexical Scoring]
Let $\mathrm{df}_t$ denote the number of documents in $\mathcal{C}$ containing term $t$, $\abs{d}$ the token length of document $d$, and $\abs{d_{\mathrm{avg}}} = \frac{1}{N}\sum_{d' \in \mathcal{C}} \abs{d'}$ the mean corpus document length. Following \bookcite{speech_language_processing_aug26}{Ch.~11, PDF pp.~265--268, Eqs.~(11.4)--(11.5), (11.12)}, logarithmic TF-IDF defines
\begin{equation}
  \mathrm{tf}_{t,d} = \begin{cases} 1 + \log_{10} \mathrm{count}(t,d) & \text{if } \mathrm{count}(t,d) > 0, \\ 0 & \text{otherwise,} \end{cases}
  \qquad \mathrm{idf}_t = \log_{10}\!\left(\frac{N}{\mathrm{df}_t}\right).
  \label{eq:rag:tfidf}
\end{equation}
Okapi BM25 replaces linear cosine normalization with bounded term-frequency saturation ($k \in [1.2, 2.0]$) and length normalization ($b \in [0, 1]$, typically $b = 0.75$):
\begin{equation}
  \mathrm{score}_{\mathrm{BM25}}(q, d) = \sum_{t \in q} \underbrace{\log\!\left(\frac{N}{\mathrm{df}_t}\right)}_{\text{IDF weight}} \cdot \underbrace{\frac{\mathrm{tf}_{t,d}\,(k + 1)}{\mathrm{tf}_{t,d} + k\!\left(1 - b + b\,\frac{\abs{d}}{\abs{d_{\mathrm{avg}}}}\right)}}_{\text{length-normalized saturated TF}},
  \label{eq:rag:bm25}
\end{equation}
or equivalently without the $(k+1)$ constant factor in the simplified form of \bookcite{speech_language_processing_aug26}{Ch.~11, PDF p.~268, Eq.~(11.12)}. Setting $k = 0$ collapses BM25 to binary term presence weighted by IDF, whereas $b = 0$ disables document-length normalization.
\end{coremath}

An \emph{inverted index} maps each vocabulary term $t$ to a postings list of $(d, \mathrm{tf}_{t,d})$ pairs, enabling exact sparse scoring in time proportional to the postings length of query terms rather than $O(N)$ \bookcite{speech_language_processing_aug26}{Ch.~11, PDF p.~268}.

\subsection{Dense Retrieval: Bi-Encoders, Cross-Encoders, and ColBERT}
\label{sec:rag:dense}

Sparse lexical matching fails when query and document use synonymous phrasing (vocabulary mismatch). Dense retrieval maps text into continuous $m$-dimensional semantic spaces via Transformer encoders \bookcite{llm_engineer_s_handbook}{Ch.~4, PDF pp.~136--140}.

\begin{coremath}[Bi-Encoder Inner Product vs. Cross-Encoder vs. ColBERT MaxSim]
Let $E_Q$ and $E_D$ denote query and document encoders producing $L_2$-normalized embeddings $\vecb{z}_q = E_Q(q) \in \R^m$ and $\vecb{z}_d = E_D(d) \in \R^m$ (e.g., from \texttt{[CLS]} or mean pooling) \bookcite{speech_language_processing_aug26}{Ch.~11, PDF p.~273, Eq.~(11.19)}:
\begin{equation}
  s_{\mathrm{bi}}(q, d) = \inner{\vecb{z}_q}{\vecb{z}_d} = \frac{E_Q(q)\T E_D(d)}{\norm{E_Q(q)}_2 \norm{E_D(d)}_2}.
  \label{eq:rag:biencoder}
\end{equation}
Because $E_D(d)$ is independent of $q$, all $N$ document vectors are precomputed offline and indexed for sub-linear Approximate Nearest Neighbor (ANN) search. Conversely, a \emph{cross-encoder} concatenates $q$ and $d$ into a single sequence $[q; \texttt{[SEP]}; d]$ and applies full self-attention across all $L_q + L_d$ tokens \bookcite{llm_engineer_s_handbook}{Ch.~4, PDF p.~154}:
\begin{equation}
  s_{\mathrm{cross}}(q, d) = \sigmoid\!\left(\vecb{w}\T \mathrm{BERT}\!\big([q; \texttt{[SEP]}; d]\big)_{\texttt{[CLS]}}\right).
  \label{eq:rag:crossencoder}
\end{equation}
Bridging both regimes, \emph{ColBERT} late interaction precomputes per-token normalized document embeddings $\vecb{E}_{d} = (\vecb{E}_{d,1}, \dots, \vecb{E}_{d,m_d})$ and computes a sum of maximum token similarities (\emph{MaxSim}) at query time \bookcite{speech_language_processing_aug26}{Ch.~11, PDF p.~274, Eq.~(11.20)}:
\begin{equation}
  s_{\mathrm{ColBERT}}(q, d) = \sum_{i=1}^{N_q} \max_{j=1,\dots,m_d} \inner{\vecb{E}_{q,i}}{\vecb{E}_{d,j}}.
  \label{eq:rag:colbert}
\end{equation}
\end{coremath}

\monographfig[0.74\textwidth]{llm_engineer_s_handbook_p154_fig1.png}{Architectural contrast between a Bi-Encoder (independent encoding and cosine similarity in $[-1, 1]$ enabling offline vector indexing) and a Cross-Encoder (joint BERT attention and classification head outputting $[0, 1]$ relevance scores for top-$K$ reranking) \bookcite{llm_engineer_s_handbook}{Ch.~4, PDF p.~154, Fig.~4.7}.}{fig:rag:bi_vs_cross}

\subsection{Hybrid Fusion (RRF) and Ranked Retrieval Evaluation}
\label{sec:rag:rrf_eval}

Because BM25 excels at exact entity/code matching while dense bi-encoders capture semantic paraphrases, production RAG systems execute both retrievers in parallel and fuse their rankings \bookcite{llm_engineer_s_handbook}{Ch.~4, PDF p.~152}.

\begin{coremath}[Reciprocal Rank Fusion (RRF) \& IR Evaluation Metrics]
Given a set of rankers $\mathcal{R} = \{\text{BM25}, \text{Dense}\}$, where $\mathrm{rank}_r(d) \in \{1, 2, \dots\}$ is the rank of chunk $d$ under ranker $r$, Reciprocal Rank Fusion aggregates rankings without requiring score-distribution calibration:
\begin{equation}
  \mathrm{RRF}(d; q) = \sum_{r \in \mathcal{R}} \frac{1}{\kappa + \mathrm{rank}_r(d)}, \qquad \kappa = 60.
  \label{eq:rag:rrf}
\end{equation}
To evaluate ranked lists against ground-truth relevance judgments $\mathrm{rel}_i \in \{0, 1, \dots\}$ over a query set $Q$ \bookcite{speech_language_processing_aug26}{Ch.~11, PDF pp.~269--272, Eqs.~(11.14)--(11.17)}, let $R_r(q)$ be the set of relevant documents for query $q$ up to cutoff $r$:
\begin{align}
  \mathrm{Recall}@k &= \frac{\abs{\text{relevant docs in top } k}}{\abs{\text{total relevant docs}}}, &
  \mathrm{MRR} &= \frac{1}{\abs{Q}} \sum_{q \in Q} \frac{1}{\mathrm{rank}_{\mathrm{first}}(q)}, \label{eq:rag:recall_mrr} \\
  \mathrm{MAP} &= \frac{1}{\abs{Q}} \sum_{q \in Q} \frac{1}{\abs{R_r(q)}} \sum_{d \in R_r(q)} \mathrm{Precision}_{\mathrm{rank}(d)}, &
  \mathrm{nDCG}@k &= \frac{1}{\mathrm{IDCG}@k} \sum_{i=1}^{k} \frac{2^{\mathrm{rel}_i} - 1}{\log_2(i + 1)}, \label{eq:rag:map_ndcg}
\end{align}
where $\mathrm{IDCG}@k$ is the ideal discounted cumulative gain of the oracle ranking.
\end{coremath}

\subsection{Approximate Nearest Neighbor Indexing: HNSW vs.\ IVF-PQ}
\label{sec:rag:ann}

Exact $k$-nearest neighbor search over $N$ vectors in $\R^m$ requires $O(Nm)$ distance evaluations, which becomes prohibitive at $N \ge 10^6$ \bookcite{llm_engineer_s_handbook}{Ch.~4, PDF p.~144}. Vector databases therefore rely on Approximate Nearest Neighbor (ANN) indices.

\begin{intuition}[HNSW Multi-Layer Graph Navigation vs.\ IVF-PQ Quantization]
\textbf{Hierarchical Navigable Small World (HNSW)} constructs a hierarchy of proximity graphs $\{G_0, G_1, \dots, G_L\}$ where layer $0$ contains all $N$ vectors and each upper layer $l$ retains an exponentially decaying subset (probability $p \propto e^{-l / m_L}$) \bookcite{llm_engineer_s_handbook}{Ch.~4, PDF p.~145}. Each node maintains at most $M$ edges ($2M$ at layer $0$). A query enters at the top layer and greedily traverses long-range skip edges down to layer $0$, where a beam search of width $\text{efSearch} \ge k$ refines the candidate set in $O(\log N)$ expected hops.

In contrast, \textbf{IVF-PQ} partitions $\R^m$ into $C_{\mathrm{list}}$ Voronoi cells via $k$-means clustering (Inverted File) and compresses residual vectors by splitting $\R^m$ into $S$ subspaces of dimension $m/S$, quantizing each sub-vector to a $b_{\mathrm{bits}}$-bit centroid code (Product Quantization) \bookcite{llm_engineer_s_handbook}{Ch.~4, PDF p.~145}. IVF-PQ reduces RAM footprint by $10\times$--$30\times$ at the cost of quantization distortion, whereas HNSW achieves higher recall@10 at the cost of storing both full vectors and graph adjacency lists in memory.
\end{intuition}

\subsection{Context Budget Optimization, Compaction, and Memory Consolidation}
\label{sec:rag:memory_math}

In multi-turn agentic workflows, unbounded session histories $\mathcal{S}_t$ exhaust $B_{\max}$ and dilute attention. \bookcite{context_engineering_sessions_memory}{pp.~23--26} formalize three session compaction triggers and a four-stage long-term memory lifecycle.

\begin{coremath}[Token-Budgeted Assembly, Compaction Triggers \& Memory Consolidation]
Partition the context budget into $B_{\mathrm{sys}} + B_{\mathrm{mem}} + B_{\mathrm{sess}} + B_{\mathrm{rag}} + B_{\mathrm{out}} \le B_{\max}$. When raw session tokens $\abs{\mathcal{S}_t}_{\mathrm{tok}}$ exceed a threshold, a compaction operator $\mathcal{K}_{\mathrm{comp}}$ fires under one of three triggers \bookcite{context_engineering_sessions_memory}{pp.~25--26}:
\begin{enumerate}
  \item \textbf{Count-based}: $\abs{\mathcal{S}_t}_{\mathrm{tok}} > \tau_{\mathrm{tok}}$ or turn count $t \equiv 0 \pmod{\Delta_{\mathrm{interval}}}$ (retaining an overlap window of $o$ recent turns).
  \item \textbf{Time-based}: Idle duration $\Delta t_{\mathrm{idle}} > \tau_{\mathrm{idle}}$ triggers asynchronous background summarization.
  \item \textbf{Event-based}: Semantic detection of sub-task completion compresses completed tool trajectories into a summary event.
\end{enumerate}
Long-term memory generation operates asynchronously on $\mathcal{S}_t$ via extraction $\mathcal{E}_\theta(\mathcal{S}_t) \to \{m_{\mathrm{cand}}\}$ filtered by domain topic schemas, followed by a consolidation operator $\mathcal{U}_{\mathrm{cons}}$ against existing memories $\mathcal{M}_{t-1}$ \bookcite{context_engineering_sessions_memory}{pp.~42--47}:
\begin{equation}
  \mathcal{M}_t = \mathcal{U}_{\mathrm{cons}}\!\big(\mathcal{M}_{t-1},\, \mathcal{E}_\theta(\mathcal{S}_t)\big) \in \{\mathrm{Create}(m_{\mathrm{new}}),\, \mathrm{Merge}(m_{\mathrm{old}}, m_{\mathrm{new}}),\, \mathrm{Delete}(m_{\mathrm{invalid}})\}.
  \label{eq:rag:consolidation}
\end{equation}
\end{coremath}

\section{Algorithmic Implementation \& Comparative Synthesis}
\label{sec:rag:algorithms}
% =============================================================================

Production RAG pipelines decouple offline ingestion (ETL $\to$ cleaning $\to$ sliding-window or small-to-big chunking $\to$ bi-encoder embedding $\to$ vector DB + feature store sync via Change Data Capture) from online inference (pre-retrieval query optimization $\to$ hybrid retrieval $\to$ post-retrieval reranking and compression) \bookcite{llm_engineer_s_handbook}{Ch.~4, PDF pp.~147--166}.

\begin{crossbook}[Cross-Book Synthesis: Declarative vs.\ Procedural Memory \& Agentic Routing]
\label{crossbook:rag:memory_routing}
Synthesizing \bookcite{context_engineering_sessions_memory}{pp.~35--38, 58--65}, \bookcite{llm_engineer_s_handbook}{Ch.~4, PDF pp.~149--153}, and \bookcite{ai_agents_2025_illustrated_guidebook}{pp.~36--41} reveals three orthogonal axes of agentic retrieval and memory design:
\begin{itemize}
  \item \textbf{Declarative vs.\ Procedural Memory}: Declarative memory stores ``knowing what''---either \emph{semantic} world/user facts (e.g., structured user profile) or \emph{episodic} interaction logs (collections pattern). Procedural memory stores ``knowing how''---reusable tool-call playbooks distilled from successful trajectories, providing fast online adaptation via in-context learning rather than slow offline RLHF/fine-tuning \bookcite{context_engineering_sessions_memory}{pp.~35, 64--65}.
  \item \textbf{Proactive vs.\ Reactive Retrieval}: Proactive retrieval (e.g., ADK \texttt{PreloadMemoryTool} callbacks) injects memories before every turn, guaranteeing availability at the cost of per-turn latency. Reactive retrieval (\texttt{Memory-as-a-Tool}) lets the LLM decide when to invoke \texttt{load\_memory(query)}, saving unnecessary lookups on chitchat turns at the expense of an extra tool-call round trip \bookcite{context_engineering_sessions_memory}{pp.~58--60}.
  \item \textbf{Agentic RAG Routing}: Rather than unconditionally querying a single vector store, an agentic router dispatches queries across heterogeneous sources---vector DBs for internal docs, SQL databases for structured records, or live web crawlers (e.g., Firecrawl) for real-time events \bookcite{llm_engineer_s_handbook}{Ch.~4, PDF p.~149}; \bookcite{ai_agents_2025_illustrated_guidebook}{pp.~36--38}.
\end{itemize}
\end{crossbook}

\section{Numerical Pitfalls, Edge Cases \& Failure Modes}
\label{sec:rag:pitfalls}
% =============================================================================

\begin{pitfall}[Chunk Boundary Severance \& Embedding Topic Dilution]
Fixed-size chunking without overlap severs sentences and cross-references at chunk boundaries, while overly large chunks aggregate multiple topics into a single blurred mean-pooled vector \bookcite{llm_engineer_s_handbook}{Ch.~4, PDF pp.~148--149}.
\textbf{Remedy:} Apply sliding-window overlap ($10\%$--$20\%$ of chunk tokens) or \emph{small-to-big} decoupling: index small, semantically focused child chunks ($128$--$256$ tokens) for sharp ANN matching, while storing the parent passage ($512$--$1024$ tokens) in metadata for LLM generation.
\end{pitfall}

\begin{pitfall}[Pre-Filtering vs.\ Post-Filtering Collapse in HNSW]
In filtered vector search \bookcite{llm_engineer_s_handbook}{Ch.~4, PDF pp.~145, 152}, applying metadata predicates \emph{after} HNSW search (post-filtering) yields fewer than $k$ results when predicate selectivity is low ($<5\%$). Conversely, naive \emph{pre-filtering} can disconnect the HNSW graph, forcing fallback to $O(N)$ brute-force scanning.
\textbf{Remedy:} Use inline predicate-aware graph traversal (ACORN / filtered-HNSW) or maintain partitioned sub-indices for high-cardinality tenant/scope keys (e.g., \texttt{user\_id} in memory stores).
\end{pitfall}

\begin{pitfall}[Dialogue Injection \& Stale Memory Lineage]
Injecting retrieved long-term memories directly into the \texttt{user} turn history risks \emph{dialogue injection}, where the LLM hallucinates that it or the user explicitly uttered the memory in the current session \bookcite{context_engineering_sessions_memory}{p.~63}. Furthermore, consolidating memories without tracking provenance/lineage propagates stale or contradictory facts across sessions \bookcite{context_engineering_sessions_memory}{pp.~49--52}.
\textbf{Remedy:} Inject declarative memories into structured system instructions (with explicit provenance timestamps and source IDs) rather than raw dialogue turns, and execute LLM-based consolidation (\texttt{Merge}/\texttt{Delete}) asynchronously against golden-set precision/recall evaluations \bookcite{context_engineering_sessions_memory}{pp.~61--65}.
\end{pitfall}

\begin{pitfall}[Context Window Saturation \& Attention Dilution]
Stuffing excessive low-ranked RAG chunks or uncompacted tool outputs into $C_t$ increases TTFT (time-to-first-token) quadratically during prefill and degrades reasoning accuracy---a failure mode where relevant evidence buried in the middle of long contexts is ignored \bookcite{context_engineering_sessions_memory}{pp.~22--24}; \bookcite{llm_engineer_s_handbook}{Ch.~4, PDF p.~153}.
\textbf{Remedy:} Enforce strict token budgets $B_{\mathrm{rag}}$ and $B_{\mathrm{sess}}$, apply cross-encoder reranking with a relevance threshold to prune noisy chunks, and trigger asynchronous recursive session compaction before $\abs{\mathcal{S}_t}_{\mathrm{tok}}$ saturates $B_{\max}$.
\end{pitfall}
